# EventQ

Aplikasi manajemen event & peserta (QR attendance, kiosk mode, hotel key
pickup, Excel import/export, generator QR/Barcode kustom).

Frontend: statis (HTML/CSS/JS klasik, tanpa build step) — deploy ke IIS/cPanel.
Backend: FastAPI + PostgreSQL (skema relasional normal, bukan lagi KV mentah).

---

## 1. Struktur file

```

styles.css                    - stylesheet global (dark mode, print, kiosk, dsb.)
js/

  cache.js     - Cache client (hydrate sekali dari /api/state, tulis per logical key)
  state.js     - state global, ID generators, kiosk/scanner state
  version.js   - APP_VERSION + changelog (Pengaturan > Tentang Aplikasi)
  i18n.js      - kamus ID/EN, t(), applyLanguage(), changeLanguage()
  storage.js   - objek LS (Cache-backed) — satu-satunya seam data
  ui.js        - toast, modal (nested + escape), pagination, progress modal, confirm
  permissions.js - hak akses fitur per user (FEATURE_PERMISSION_GROUPS, hasFeaturePerm)
  darkmode.js  - toggle & apply dark mode
  sync.js      - BroadcastChannel sync antar tab (kiosk <-> dashboard)
  settings.js  - logo, background login (slideshow), storage meter, kiosk/caption settings
  auth.js      - login, register, recovery, logout
  users.js     - kelola pengguna + kelola akses fitur
  events.js    - library event (grid/list, filter, sort), CRUD, duplikat, share, enter/exit
  tools.js     - Custom QR Code & Barcode Generator (CRUD, preview, scan pembaca)
  guests.js    - peserta: form, dashboard, tabel, sorting, Excel import/export
  scanner.js   - scan kehadiran (tab Scan)
  signature.js - tanda tangan pengambilan kunci (bukan kiosk)
  print.js     - pembuatan kartu cetak QR peserta/QR kustom/barcode kustom
  kiosk.js     - mode kiosk (absensi/pengambilan/cek data), PIN exit, TTS, beep, signature
  main.js      - bootstrap window.onload + jaring pengaman error global
backend(api)/
  app/main.py  - endpoint: /api/health, /api/state, /api/state/{key}
  app/db.py    - mapping logical key <-> tabel relasional + migrasi legacy KV
  app/config.py, .env - konfigurasi (.env TIDAK di-commit; isi kredensial asli di server)

web.config                  - reverse proxy IIS: /api/* -> http://192.168.90.93:3000

```

Urutan load script di `index.html` penting (script klasik berbagi satu global
scope): config → cache → state → version → i18n → storage → ui → permissions →
darkmode → sync → settings → auth → users → events → tools → guests → scanner →
signature → print → kiosk → main.

## 2. Setup database PostgreSQL

```bash
sudo -u postgres psql
```
```sql
CREATE DATABASE eventq;
CREATE USER eventq_user WITH ENCRYPTED PASSWORD 'CHANGE_ME';
GRANT ALL PRIVILEGES ON DATABASE eventq TO eventq_user;
\c eventq
\i /path/to/EventQ_Database_Schema.sql
\q
```

Skema ini idempotent (aman dijalankan ulang). Berisi:

- 11 tabel normal: `users`, `user_feature_permissions`, `events`,
  `event_custom_fields`, `event_shared_access`, `guests`,
  `guest_custom_field_values`, `custom_qr_codes`, `custom_barcodes`,
  `login_bg_images`, `app_settings`.
- Trigger `updated_at` otomatis (pengganti `ON UPDATE CURRENT_TIMESTAMP` MySQL).
- Seed `app_settings` + 1 akun `superadmin` contoh
  (password `ubah_password_ini` — WAJIB diganti setelah instalasi).
- `eventq_kv` **dipertahankan sementara** untuk migrasi data lama (lihat §5).

Konversi dari skema MySQL teman Anda (`newVersion/EventQ_Database_Schema.sql`):
AUTO_INCREMENT → `GENERATED BY DEFAULT AS IDENTITY`, ENUM → `VARCHAR + CHECK`,
JSON → `JSONB`, `ON UPDATE CURRENT_TIMESTAMP` → trigger, seed `ON CONFLICT DO
NOTHING`.

## 3. Backend

```bash
cd backend(api)
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env 2>/dev/null || true
# edit .env: DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD (jangan commit!)
uvicorn app.main:app --host 0.0.0.0 --port 3000
```

Endpoint (sengaja dibuat kecil — tidak ada REST CRUD penuh):

| Endpoint | Fungsi |
|---|---|
| `GET /api/health` | health check (dipakai splash screen) |
| `GET /api/state` | seluruh state aplikasi diproyeksikan ke bentuk logical key lama (`qis_users`, `qis_events`, `qis_guests_<id>`, `qis_setting_*`, ...) |
| `PUT /api/state/{key}` | tulis satu logical key; backend memetakan ke tabel relasional dalam satu transaksi |
| `DELETE /api/state/{key}` | hapus satu logical key/data set |

Frontend tetap memakai `LS.*` (synchronous, in-memory via `Cache`) — perubahan
hanya di bawahnya: hydrate dari `/api/state`, tulis ke `/api/state/{key}`.

### Migrasi data lama (KV → relasional)

Jika `eventq_kv` masih berisi data dari backend lama, `db.init_db()` akan
memigrasikannya **sekali, otomatis, idempotent** saat startup pertama (ditandai
`app_settings._legacy_migrated`). Pemetaan field lama → baru sudah ditangani
di `backend(api)/app/db.py` (`name→full_name`, `password→password_hash`,
`profilePic→profile_picture_url`, `type→event_type`, `logo→logo_url`,
`nama→full_name`, `rs→institution_origin`, `jabatan→position`,
`kursi→seat_number`, `kamar→room_number`, `kunciDiambil→key_picked_up`,
`scanned→attendance_scanned`, dst).

Setelah yakin migrasi berhasil, tabel KV bisa dihapus:

```sql
DROP TABLE IF EXISTS eventq_kv;
```

### Catatan keamanan password

Saat ini frontend masih membandingkan password secara langsung di browser
(`auth.js`), sehingga kolom `users.password_hash` sementara berisi nilai
plaintext agar kompatibel dengan akun lama dan seed `superadmin`. **Jangan
menggunakan password produksi dengan konfigurasi ini.**

Untuk produksi, langkah berikutnya adalah menambahkan endpoint login backend,
hash seluruh password dengan bcrypt (mis. `passlib`), lalu menghapus password
dari respons `/api/state` dan dari logika login frontend. UI tidak menampilkan
atau mengekspor password.

## 4. Frontend deploy (IIS / inetpub)

1. Salin `index.html`, `styles.css`, folder `js/` ke folder situs.
2. `web.config` sudah mem-proxy `(api)/(.*)` → `http://192.168.90.93:3000/{R:0}`
   — `js/config.js` memakai `window.API_BASE = '/EventQ/api'`, sesuaikan bila
   path situsnya beda.
3. Tidak ada build step — semua `js/*.js` adalah script klasik yang saling
   berbagi global scope.

## 5. Verifikasi cepat

1. `curl http://<backend>:3000/api/health` → `{"status":"ok"}`
2. Buka aplikasi → splash "Mempersiapkan Event Library..." → login muncul.
3. Jalankan `EventQ_Database_Schema.sql` dua kali → tidak ada error (idempotent).
4. Setelah deploy, cek DevTools → Network: satu `GET /api/state` saat load,
   `PUT /api/state/<key>` tiap ada perubahan data.
